## Rehearsal decisions

- One primary live path: the deployed attendee interaction and real report refresh. Have the pinned repository and approved task ready in separate tabs.
- Managed previews are password-protected. Rehearse on the presentation laptop using privately supplied access. Agree attendee access separately before placing a preview URL on a QR code; do not print its password or report key on stage.
- If the new task does not complete, show the local app and explicitly label it local. Use previously verified QuestPass evidence as a separate historical example; never splice its payment receipt into a claimed Dev Day Pulse end-to-end run.
- If network or login fails on stage, switch to saved screenshots or the existing submitted film. Identify prerecorded evidence; do not simulate a successful live payment or deployment.
- Do not display passwords, private report keys, API keys, `.env`, wallet export screens, raw private messages or account balances.
- The flash track is not announced yet. Keep this app easy to adapt, but do not invent its requirements.
